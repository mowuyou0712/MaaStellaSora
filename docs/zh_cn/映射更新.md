# 映射更新

发行包根目录带有 `mss_update.py` 和 `update_mapping.json`，用于把 GitHub 官方地址替换成可用镜像，完成版本检查、下载与安装。GitHub 直连不稳、又不想依赖 Mirror酱 CDK 时使用这种方式。

它和客户端自带更新、`mirrorchyan_rid` 对应的 Mirror酱通道互不影响：三者安装的是同一个发行包，只是取包路径不同。

## 发行包内的文件

| 文件                    | 说明                       |
| --------------------- | ------------------------ |
| `mss_update.py`       | 更新器，只依赖标准库               |
| `update_mapping.json` | 映射表，换源只需要改它              |
| `.update/`            | 运行时生成，存放下载缓存、备份和状态，可随时删除 |

源码位于 `tools/updater/`，由 `tools/ci/package_common.py` 的 `PROJECT_FILES` 复制到发行包根目录。

## 快速开始

先完全退出 MFAAvalonia（包括托盘图标），再在发行包目录执行：

```bat
python\python.exe mss_update.py --check
python\python.exe mss_update.py --yes
```

Linux 与 macOS 使用系统 Python：

```sh
python3 mss_update.py --check
python3 mss_update.py --yes
```

只检查时不下载；带 `--yes` 会依次检查、下载、校验并覆盖安装。目标目录默认是脚本所在目录，可用 `--dir` 指定其他安装位置。

## 映射表

映射表决定官方地址如何改写，字段如下。

| 字段                  | 说明                                  |
| ------------------- | ----------------------------------- |
| `repo`、`api`        | 仓库与 API 模板，换项目时一起改                  |
| `asset_pattern`     | 安装包命名规则，`{platform}` 取自 `platforms` |
| `platforms`         | 平台标签到压缩格式的对应关系                      |
| `mirrors`           | 镜像列表，`prefix` 拼接在官方地址之前             |
| `mirrors[].scopes`  | `api` 表示查询版本，`download` 表示下载安装包     |
| `mirrors[].enabled` | 设为 `false` 可临时停用而不删除条目              |
| `protected_paths`   | 永不覆盖的目录，例如 `config`、`debug`、`logs`  |
| `managed_dirs`      | 允许清理旧版本残留文件的目录                      |

映射效果：

```text
https://api.github.com/repos/MaaStellaSora/MaaStellaSora/releases/latest
  -> https://gh-proxy.com/https://api.github.com/repos/MaaStellaSora/MaaStellaSora/releases/latest

https://github.com/MaaStellaSora/MaaStellaSora/releases/download/v1.7.0/MaaStellaSora-win-x86_64-v1.7.0.zip
  -> https://gh-proxy.com/https://github.com/MaaStellaSora/MaaStellaSora/releases/download/v1.7.0/...
```

新增镜像就是在 `mirrors` 里加一条，`scopes` 按镜像实际能力填写：只代理下载的镜像不要写 `api`，否则每次检查版本都会先等它超时。

## 常用参数

| 参数                         | 作用                     |
| -------------------------- | ---------------------- |
| `--check`                  | 只检查是否有新版本              |
| `--yes`、`-y`               | 跳过确认                   |
| `--dry-run`                | 下载并解包，只列出将要改动的文件       |
| `--pre`                    | 允许预发布版本                |
| `--platform`               | 覆盖平台标签，例如 `win-x86_64` |
| `--dir`                    | 指定客户端目录                |
| `--mapping`                | 使用另一份映射表               |
| `--test-mirrors`           | 打印各镜像的可用性与速度           |
| `--restore latest`         | 回滚到最近一次备份              |
| `--no-backup`、`--no-prune` | 不备份、不清理旧残留             |
| `--force`                  | 版本不新也重新安装              |

## 执行过程

1. 按映射表顺序读取 `releases/latest`，第一个可用的镜像返回版本信息。
2. 依据平台标签挑选 Release 资产，例如 `win-x86_64`、`linux-aarch64`、`android-arm64-v8a`。
3. 对下载镜像并行预取 64KB 测速，较快的镜像先下载，失败时自动换下一个。
4. 写入 `.update/cache/*.part` 并支持 Range 续传，中断后重新运行会接着下载。
5. 比对 Release 资产自带的 SHA-256 摘要，不一致时删除该文件并更换镜像。
6. 解包到 `.update/staging`，拒绝绝对路径和 `..` 之类的非法条目。
7. 被覆盖或删除的文件改名移入 `.update/backup/<时间戳>/`。
8. 内容相同的文件跳过，其余先写临时文件再改名替换。
9. 清理 `managed_dirs` 中旧版本残留的文件。
10. 把版本、镜像、校验值和备份名写入 `.update/state.json`。

`config`、`debug`、`logs` 等目录既不参与同步也不参与清理，登录状态和任务配置会保留。

## 回滚

更新失败或新版本异常时，在发行包目录执行：

```bat
python\python.exe mss_update.py --restore latest
```

也可以指定备份目录名，即 `.update/backup/` 下的时间戳。回滚只还原被覆盖或删除的文件，不会删除新版本新增的文件。

## 常见问题

- 所有镜像都不可用：先运行 `--test-mirrors` 确认是全部不通还是个别镜像失效，失效的条目设 `"enabled": false`，全部不通时补充新镜像或在本机代理下使用直连。
- 下载中断：重新运行即可续传，需要重来时删除 `.update/cache/`。
- 提示客户端还在运行：更新会替换 `MFAAvalonia.exe` 和 Python 运行时，被占用时必然失败，需要先从托盘退出。
- 校验值持续不符：多为镜像缓存了旧文件，删除 `.update/cache/` 后重试。
- 安卓端：`--platform android-arm64-v8a` 只下载 APK，安装仍需手动进行。

## 维护镜像

镜像可用性会变化，改动映射表后按下列方式确认，并在 PR 中附上实测结果：

```sh
python3 mss_update.py --test-mirrors
```

2026 年 10 月 21 日的实测结果：`gh-proxy`、`gh.llkk.cc` 的 API 与下载均可用；`ghfast`、`ghproxy.net` 仅下载可用。镜像清单变化时同步更新本节。
